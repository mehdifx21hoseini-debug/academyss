# MENTORAI — کد سیستم

وضعیت: **مرحله ۰ تا ۳ پیاده‌سازی شده.** سیستم پیام دریافت و ذخیره می‌کند و هنوز هیچ
پاسخی تولید یا ارسال نمی‌کند.

معماری در `../docs/ARCHITECTURE.md`، تصمیم‌ها در `../docs/ARCHITECTURE_DECISIONS.md`،
و الزامات حفاظت حساب در `../docs/TELEGRAM_SAFETY.md`.

## آنچه الان کار می‌کند

- اتصال هم‌زمان به چند حساب تلگرام از طریق MTProto
- فیلتر ورودی: فقط گفتگوی خصوصی دونفره، هرگز گروه و کانال، با فهرست استثنا
- تشخیص پیام تکراری با قید یکتایی پایگاه داده، اتمی و مقاوم در برابر هم‌زمانی
- ذخیره‌ی مکالمه و پیام، با تفکیک فرستنده بین دانشجو و منتور
- تشخیص هویت: یک دانشجو می‌تواند چند هویت تلگرامی داشته باشد
- وضعیت مکالمه با گذارهای صریح؛ گذار نامعتبر خطا می‌دهد
- لایه‌ی دسترسی مشترک: منتور فقط دانشجویان خودش را می‌بیند، با محدودسازی داخل پرس‌وجو
- پایگاه دانش: ورود از CSV، قطعه‌بندی، تفکیک منبع رسمی از تجربه‌ی منتور، تاریخ انقضا
- بازیابی ترکیبی: جستجوی برداری با pgvector در کنار جستجوی متنی، با ترکیب رتبه‌ها
- ابزار ارزیابی بازیابی با recall و MRR
- لایه تصمیم دو مرحله‌ای: قواعد قطعی پیش از مدل، سپس خروجی ساختاریافته
- ثبت کامل هر اجرا: مدل، تأخیر، توکن، اسناد بازیابی‌شده با امتیازشان، تصمیم و دلیلش
- حالت پیش‌نویس با ربات کنترل منتور، و ارسال مستقیم به‌عنوان یک تنظیم
- صف کار روی پستگرس با `FOR UPDATE SKIP LOCKED`
- نرمال‌سازی فارسی، یک تابع مشترک برای ذخیره و جستجو
- محدودکننده‌ی نرخ، ساعات سکوت، عقب‌نشینی FloodWait، کلید قطع هر حساب
- نشست MTProto رمزنگاری‌شده در حالت سکون

## رفتار در برابر پیام بی‌پاسخ

وقتی سیستم مطمئن نیست، **هیچ اثری در تلگرام نمی‌گذارد**: پیام خوانده علامت نمی‌خورد،
نشانگر تایپ نشان داده نمی‌شود، و چیزی ارسال نمی‌شود. پیام خوانده‌نشده می‌ماند تا در
تلگرام خودِ منتور دیده شود (ADR-009).

تنها جایی که علامت خوانده‌شدن فرستاده می‌شود `telegram/sender.py` است، و فقط تا شناسه‌ی
پیامی که واقعاً پاسخ گرفته. اگر پیام بعدی جواب نگرفته باشد، خوانده‌نشده می‌ماند.

## حالت پاسخ‌دهی

هر حساب یک تنظیم `reply_mode` دارد:

- `draft` — پاسخ به ربات کنترل می‌رود، منتور تأیید یا ویرایش یا رد می‌کند
- `auto` — پاسخ مستقیم از حساب همان منتور به دانشجو می‌رود

سوییچ بین این دو یک تغییر مقدار در پایگاه داده است، نه تغییر کد (ADR-010).

```bash
mentorai run-worker   # کارگر و ربات کنترل
```

در ربات کنترل، هر منتور یک‌بار `/link <slug>` می‌زند تا گفتگویش به حسابش وصل شود.

## پایگاه دانش

```bash
mentorai kb-import --file ../knowledge-base/kb.csv
mentorai kb-eval --cases ../knowledge-base/eval.csv --k 5
```

مدل تعبیه‌سازی هنوز انتخاب نشده. تا آن موقع بردارساز آزمایشی استفاده می‌شود که شباهت
معنایی نمی‌دهد و فقط برای آزمودن لوله‌کشی است. انتخاب مدل واقعی باید با اجرای `kb-eval`
روی چند گزینه و مقایسه‌ی اعداد انجام شود، نه پیش از آن.

راهنمای جمع‌آوری محتوا در `../docs/KNOWLEDGE_BASE.md`.

## اجرا

```bash
cp .env.example .env          # مقادیر واقعی را پر کنید
docker compose up -d db
docker compose run --rm gateway python -m alembic upgrade head

# یک‌بار برای هر منتور
docker compose run --rm gateway mentorai add-account \
    --slug mentor-a --mentor-name "نام منتور" --phone "+98..."
docker compose run --rm -it gateway mentorai login --slug mentor-a

docker compose up -d gateway
```

ورود عمداً دستی و تعاملی است. ورود مکرر خودش برای تلگرام سیگنال منفی است، پس این
دستور نباید در راه‌اندازی خودکار قرار بگیرد.

## توقف یک حساب

```bash
mentorai pause --slug mentor-a --reason "بررسی محدودیت"
mentorai pause --slug mentor-a --resume
```

سه حساب مستقل‌اند؛ توقف یکی بقیه را متوقف نمی‌کند.

## استثنا کردن یک گفتگو

```bash
mentorai exclude-chat --slug mentor-a --peer-id 123456789 --reason "همکار"
```

## توسعه

```bash
python3.12 -m venv .venv && .venv/bin/pip install -e ".[dev]"
createdb mentorai_test

.venv/bin/python -m pytest        # تست‌ها روی پستگرس واقعی اجرا می‌شوند
.venv/bin/python -m ruff check src tests
.venv/bin/python -m mypy
```

تست‌ها طرح داده را از خود فایل‌های مهاجرت می‌سازند، نه از مدل‌ها. منبع حقیقت طرح داده
مهاجرت‌هاست؛ اگر تست روی طرحی اجرا شود که از مدل ساخته شده، واگرایی این دو تا محیط
تولید پنهان می‌ماند.

## نکته‌های امنیتی که هنگام تغییر کد باید رعایت شوند

- نشست MTProto اختیار کامل حساب را دارد. هرگز لاگ نمی‌شود، هرگز از هیچ رابطی برنمی‌گردد.
- متن پیام و نام و شماره‌ی دانشجو در سطح INFO یا بالاتر لاگ نمی‌شود.
- هیچ فراخوانی علامت‌گذاری خوانده‌شدن در مسیر دریافت وجود ندارد و نباید اضافه شود.

قوانین کامل در `../.claude/skills/mentorai-security/SKILL.md`.
