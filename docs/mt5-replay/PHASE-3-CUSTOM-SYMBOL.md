## دو قانونی که در Sink اعمال می‌شوند

### ۱. Warmup با کندل می‌رود، Replay با تیک

| | مسیر | چرا |
|---|---|---|
| Warmup (صد هزار کندل) | `CustomRatesUpdate` | تزریق تیکی چند دقیقه طول می‌کشد و صدهزار به‌روزرسانی چارت پخش می‌کند که کسی نمی‌بیند |
| Replay | `CustomTicksAdd` | نوشتن کندل، ساخت زنده کندل را حذف می‌کند — که کل هدف است |

### ۲. Truncate یعنی حذف، نه مخفی‌سازی

Rewind کندل‌ها و تیک‌ها را از **حافظه خود MetaTrader** پاک می‌کند. آینده‌ی مخفی‌شده‌ولی‌موجود، دقیقاً همان شکست‌مدی است که این محصول برای اجتنابش وجود دارد.

## ⚠️ اصلاح قرارداد Phase 1 — با دلیل

گفتم اگر مجبور شوم Core را عوض کنم صریح می‌گویم. **این‌بار قرارداد Phase 1 واقعاً ناقص بود.**

### مشکل

`TruncateFrom` مقدار `bool` برمی‌گرداند. اما MetaTrader کندل‌های M1 و تیک‌ها را **جداگانه** ذخیره می‌کند، و **حذف تیک، کندلی را که آن تیک قبلاً ساخته، از حالت ساخته‌شده خارج نمی‌کند.**

یعنی اگر وسط یک کندل برش بزنیم:

```
کندل 10:35  [10:35:00 ─────────── 10:35:59]
                        ▲ برش در 10:35:20
تیک‌های بعد از 10:35:20 حذف می‌شوند ✓
اما کندل 10:35 هنوز High/Low خودش را از تیک‌های حذف‌شده دارد ✗
```

**نتیجه: یک نشت آینده که هیچ ظاهری از خرابی ندارد.**

### اصلاح

```
virtual long TruncateFrom(const long from_msc) = 0;
```

Sink حالا **جایی را که واقعاً برش زده** برمی‌گرداند — همیشه یک مرز کندل. کنترلر Cursor را با **پاسخ Sink** هماهنگ می‌کند، نه با درخواست خودش.

### اصلاح دوم که لازم شد

اگر شروع Replay وسط یک دقیقه انتخاب می‌شد، اولین Truncate روی مرز کندل *قبل* از شروع می‌افتاد و **بخشی از Warmup را حذف می‌کرد**.

حل: `SetWindow` حالا شروع را به مرز M1 **Snap** می‌کند. Replay همیشه از ابتدای یک دقیقه شروع می‌شود.

### اصلاح سوم — Seek اتمیک شد

بعد از برش رو به عقب، فاصله بین نقطه برش و ساعت باید فوراً پر شود، وگرنه چارت تا Pump بعدی یک حفره نشان می‌دهد. حالا هر دو جهت Seek بلافاصله داده بدهکار را منتشر می‌کنند.

## Code Review — یک ضعف واقعی

### 🐞 جلسه‌ی Crash کرده، جلسه‌ی بعدی را قفل می‌کرد (High)

اگر جلسه قبلی Crash می‌کرد، نماد Replay با یک چارت باز باقی می‌ماند. `Destroy()` شکست می‌خورد، `CustomSymbolCreate` نام موجود را رد می‌کرد، و **کاربر تا پاک‌سازی دستی اصلاً نمی‌توانست جلسه جدید شروع کند**.

**اصلاح:** اگر ساخت شکست خورد و نماد موجود **قابل‌اثبات مال ماست** (پسوند `.SSR`)، به‌جای امتناع، آن را **تحویل می‌گیریم** و تاریخچه‌اش را پاک می‌کنیم.

تست `T3.7` عمداً یک نماد رها می‌کند و مسیر تحویل‌گیری را می‌آزماید.

### 🔧 Cleanup گسترش یافت

`SSR_Z_Cleanup` حالا نمادهای محصول (`<origin>.SSR<slot>`) را هم پاک می‌کند، نه فقط نمادهای Spike.

## تطبیق API با مستندات MQL5

| API | استفاده | نکته اعمال‌شده |
|---|---|---|
| `CustomSymbolCreate(name, path, origin)` | ساخت | پارامتر سوم مشخصات را کپی می‌کند — دستی نمی‌نویسیم |
| `CustomSymbolDelete` | تخریب | با چارت باز یا در Market Watch شکست می‌خورد → ترتیب اجباری |
| `CustomSymbolSetSessionQuote/Trade` | ۲۴/۷ | جلوگیری از حذف خاموش تیک (Spike B3) |
| `CustomRatesUpdate` | Warmup | برش‌برش ۱۰٬۰۰۰تایی |
| `CustomRatesDelete(sym, datetime, datetime)` | Truncate | ورودی `datetime` است، پس برش روی مرز کندل |
| `CustomTicksAdd` | Replay | نیازمند حضور در Market Watch؛ مقدار برگشتی می‌تواند کمتر باشد → شمرده می‌شود |
| `CustomTicksDelete(sym, long, long)` | Truncate | ورودی میلی‌ثانیه است |
| `SYMBOL_TIME_MSC` | ساعت | ادعای «برد رایگان» سند طراحی — T3.4 می‌سنجدش |
