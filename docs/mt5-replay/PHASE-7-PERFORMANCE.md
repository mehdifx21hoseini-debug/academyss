## یافته‌ای که جهت این Phase را عوض کرد

قبل از نوشتن کد، حساب کردم گلوگاه کجاست. نتیجه، **فرض سند طراحی را رد کرد**:

| سرعت | ثانیه Replay بر ثانیه واقعی | کندل M1/ثانیه | تیک/ثانیه |
|---:|---:|---:|---:|
| 1x | 1 | 0.017 | **0.13** |
| 10x | 10 | 0.167 | **1.3** |
| 50x | 50 | 0.833 | **6.7** |

**هدف «۲۰۰۰ تیک بر ثانیه» به سرعت ۱۵٬۰۰۰x مربوط می‌شود، نه به ۵۰x.**

جدول Adaptive Fidelity سند طراحی (Tick واقعی زیر 2x، مصنوعی تا 10x، Bar بالاتر) مسئله‌ای را حل می‌کرد که **در این سرعت‌ها وجود ندارد**.

### یافته دوم: 50x اصلاً سریع نیست

| سرعت | یک روز معامله |
|---:|---:|
| 1x | ۲۴ ساعت |
| 10x | ۲.۴ ساعت |
| 50x | **۲۹ دقیقه** |

پس Fast-Forward واقعی باید **Jump** باشد (Phase 8)، نه ضریب سرعت بزرگ‌تر. نردبان سرعت طبق خواسته‌ی تو دست‌نخورده ماند.

## پس Fidelity برای چه چیزی افت می‌کند؟

سه دلیل **واقعی**، نه سرعت:

| # | دلیل | چرا واقعی است |
|---|---|---|
| ۱ | **داده نیست** | اکثر بروکرها برای CFD تیک تاریخی ندارند؛ تظاهر به داشتنش یعنی نمایش بازار یخ‌زده |
| ۲ | **لحظه‌ی انبوه** | Pump بعد از یک مکث، یا Jump روی چند ساعت — تنها جایی که یک فراخوانی واقعاً دقایقی کار دارد |
| ۳ | **کاربر خواست** | انتخاب او بر سیاست ارجح است؛ `LockFidelity` سیاست را کنار می‌گذارد |

و **هر تصمیمی همیشه دیده می‌شود**. پنل Fidelity **در حال اجرا** را نشان می‌دهد نه درخواست‌شده را، با ستاره وقتی افت کرده و دلیلش در نوار هشدار.

> ابزاری که در سکوت تقریب می‌زند، درباره‌ی خروجی خودش دروغ می‌گوید.

## قانون این Phase: هیچ ادعا بدون اندازه‌گیری

### موتور خودش را می‌سنجد

```
RecordPump(total_us, emit_us, ticks, bars, deferred)
RecordSeed(bars, ms)
```

- **µs بر تیک** — فقط از Pumpهایی که واقعاً تیک منتشر کردند. Pump بیکار چیزی درباره‌ی هزینه نمی‌گوید و نباید میانگین را رقیق کند (تست `T7.2`).
- **p50 / p95 / max** روی حلقه‌ی ۲۵۶ نمونه‌ای
- **نرخ Seed** — که به کاتالوگ برمی‌گردد

### سقف Pump دیگر ثابت نیست

```
SSR_MAX_BARS_PER_PUMP = 512        ← حذف شد
MaxTicks() = budget_ms / measured_us_per_tick
```

بودجه بر اساس **ادراک انسانی** انتخاب شده نه Throughput: زیر ~۱۶ms مکث نامرئی است، بالای ۵۰ms لکنت خوانده می‌شود. پیش‌فرض ۱۲ms.

و وقتی هنوز کالیبره نشده، **می‌گوید**:

```
budget[12ms -> 4096 ticks UNCALIBRATED deferred=0]
budget[12ms -> 1140 ticks measured deferred=3]
```

### نقل قیمت از تخمین به واقعیت

Seed خودش را می‌سنجد و عدد را به `CSSRHistoryCatalog` می‌دهد. جلسه‌ی دوم کاربر **از جلسه‌ی اول او** قیمت می‌خورد، نه از ثابتی که کسی تایپ کرده.

```
q.measured == false  →  "about 12s"
q.measured == true   →  "12s"
```

## ثابت‌های حدسی — وضعیت نهایی

| ثابت | قبل | حالا |
|---|---|---|
| `SSR_MAX_BARS_PER_PUMP` | ۵۱۲ حدسی | **حذف شد** — از اندازه‌گیری مشتق می‌شود |
| `SSR_WINDOW_BARS_DEFAULT` | ۲۰٬۰۰۰ ثابت | فقط Fallback؛ اندازه واقعی از `SuggestWindowBars` |
| `SSR_TICKS_CHUNK` | تنظیم Throughput | **کران ایمنی** یک فراخوانی API — بودجه از قبل مهارش کرده |
| `SSR_REDRAW_MIN_INTERVAL_MS` | حدسی | **توجیه ادراکی**: ۱۰ فریم بر ثانیه از آستانه پیوستگی بصری گذشته |
| `SSR_METRIC_SAMPLES` | — | چند ثانیه پخش: کافی که یک فریم کند p95 را نبرد، کوتاه که هنوز «الان» را توصیف کند |
| `SSR_SYNC_TIMEOUT_MS` | — | سخاوتمند عمداً: تسلیم زودهنگام «داده نیست» گزارش می‌دهد برای نمادی که فقط هنوز نرسیده |
| `SSR_TICK_PAGE_GUARD` | — | توقف سخت، نه تنظیم: تا Providerی که پیشرفت نمی‌کند بی‌نهایت نچرخد |
