# مقایسه‌ی کور مدل‌ها

سؤالی که این ابزار جواب می‌دهد: **کدام مدل پیش‌نویس‌هایی می‌نویسد که منتور کمتر بازنویسی
کند؟** همین سنجه‌ی اصلی پروژه است (ADR-018)، نه «کدام باهوش‌تر است».

هر پرسش با **همان سندها** و **همان دستور تولید** به همه‌ی مدل‌ها داده می‌شود و نتیجه از
**همان دروازه‌ی تولید** می‌گذرد (آستانه‌ی اطمینان، نگهبان قیمت). پاسخ‌ها بدون نام مدل و با
ترتیب تصادفی در یک فایل می‌آیند، منتور امتیاز می‌دهد، و بعد گزارش نشان می‌دهد کدام بهتر بوده.

## پیش از شروع

- سیستم روی سرور بالا باشد، پایگاه دانش وارد شده باشد، و `mentorai model-check` همه‌ی
  مدل‌هایی را که می‌خواهید بسنجید سبز بدهد (`docs/SERVER_SETUP.md`، بخش ۹٫۵).
- کلید هر ارائه‌دهنده در `.env` باشد: `ANTHROPIC_API_KEY` و برای OpenAI `OPENAI_API_KEY`.
- پوشه‌ی خروجی را یک بار بسازید. این‌جا پیام واقعی دانشجو می‌نشیند، پس فقط برای شما باز است:

```bash
cd ~/academyss/mentorai
mkdir -p model-compare && chown 10001 model-compare && chmod 700 model-compare
```

## ۱. شمارش بدون هزینه

`--dry-run` فقط پرسش‌ها را می‌شمارد و هیچ مدلی را صدا نمی‌زند:

```bash
docker compose run --rm cli mentorai compare-run \
  --candidate anthropic:claude-sonnet-5-5:medium \
  --candidate anthropic:claude-opus-5-5:medium \
  --cases /kb/mentorai_eval_latest.csv --limit 60 --dry-run
```

می‌گوید چند پرسش به مدل‌ها می‌رسد و چند تا کنار گذاشته می‌شود (پرسشی که مدل در تولید هم
نمی‌دیدش: پول، شکایت، حساب، درخواست منتور، یا بی‌سند).

**قالب نامزد:** `ارائه‌دهنده:مدل:عمق‌فکر`. مدل OpenAI یا هر مدلی که در جدول قیمت نیست، قیمت
هر میلیون توکن را (از صفحه‌ی قیمت ارائه‌دهنده) به‌شکل `@ورودی/خروجی` می‌گیرد:

```
--candidate openai:<نام مدل>:low@<قیمت ورودی>/<قیمت خروجی>
```

## ۲. اجرای واقعی (هزینه دارد)

```bash
docker compose run --rm cli mentorai compare-run \
  --candidate anthropic:claude-sonnet-5-5:medium \
  --candidate anthropic:claude-opus-5-5:medium \
  --cases /kb/mentorai_eval_latest.csv --limit 60 \
  --max-cost-usd 5 --out /out/run1
```

- پس از **نخستین پرسش**، هزینه‌ی کل برآورد می‌شود. اگر از `--max-cost-usd` بگذرد، همان‌جا با
  چند سنت خرج متوقف می‌شود و می‌گوید چه کنید.
- اگر وسط کار به سقف برسد، آنچه را اجرا شده نگه می‌دارد و گزارش هشدار می‌دهد.

سه فایل در `model-compare/run1/` ساخته می‌شود:

| فایل | به که می‌دهید |
|---|---|
| `blind_sheet.csv` | منتور (داور) |
| `grader_guide.txt` | منتور (داور) |
| `key.json` | **هیچ‌کس تا پایان داوری.** نام مدل هر پاسخ فقط اینجاست |

## ۳. کدام پرسش‌ها

| منبع | چه زمانی |
|---|---|
| `--cases /kb/mentorai_eval_latest.csv` | همین حالا، برای آزمودن خود ابزار و یک نشانه‌ی اول. پرسش‌ها بازنویسی‌های ساختگی‌اند، نه حرف واقعی دانشجو |
| `--from-db 80` | **برای تصمیم نهایی.** پیام‌های متنی واقعی دانشجوها، از ۵۰۰۰ پیام اخیر، بدون تکراری و بدون گفتگوهای استثناشده. بعد از هفته‌ی آزمایش |

⚠️ فایل‌های `--from-db` پیام واقعی دانشجو دارند. ایمیل، نام کاربری تلگرام و هر رشته‌ی
۹ رقمی یا بیشتر پوشانده می‌شود، حتی اگر با فاصله یا خط تیره نوشته شده باشد (`0912 345 6789`،
کارت ۴-۴-۴-۴). ضمناً چند عدد بازار پشت‌هم یا تاریخ با ساعت هم ممکن است پوشانده شود؛ پوشاندن
اضافه بهتر از جا ماندن شماره است. نام و جزئیات دیگر می‌مانند. به مخزن نمی‌روند (`model-compare/`
در `.gitignore` است)؛ فقط برای منتورهایی بفرستید که خودشان این دانشجوها را می‌بینند.

## ۴. داوری

متن دانشجو و پاسخ مدل نامطمئن‌اند. سلولی که با `=` یا `+` یا `-` یا `@` شروع شود در برگه با یک `'`
جلویش می‌آید تا اکسل آن را فرمول اجرا نکند؛ اگر چنین چیزی دیدید، همین است.


منتور `blind_sheet.csv` را در اکسل باز می‌کند. برای هر پاسخ دو ستون را پر می‌کند:

- **امتیاز** (۰ تا ۳): ۳ = همین را می‌شد فرستاد، ۲ = ویرایش کوچک، ۱ = بازنویسی کامل، ۰ = غلط یا خطرناک.
- **ساخته‌شده** (۱ یا خالی): پاسخ چیزی گفته که در «منابع» نیست.

راهنمای کاملش در `grader_guide.txt` است. بعد فایل را با همان نام و قالب CSV UTF-8 یا xlsx ذخیره
می‌کند. ۶۰ پرسش با ۲ پاسخ، حدود یک ساعت کار است.

نکته: با دو منتور جداگانه هم می‌شود داوری کرد؛ هر کدام فایل خودشان را پر می‌کنند و گزارش جدا
می‌گیرید. اگر نتیجه‌ها با هم نخواند، خودِ پرسش‌ها مبهم‌اند، نه مدل‌ها.

## ۵. گزارش

فایل پرشده را کنار کلید بگذارید (`model-compare/run1/`) و برای کاربر کانتینر خواندنی کنید.
(فایلی که با root می‌گذارید معمولاً مجوز ۶۰۰ دارد و کانتینر نمی‌تواند بازش کند.)

```bash
chmod 644 model-compare/run1/blind_sheet_filled.csv
```

بعد:

```bash
docker compose run --rm cli mentorai compare-report \
  --key /out/run1/key.json --graded /out/run1/blind_sheet_filled.csv
```

برای هر مدل می‌گوید:

- میانگین امتیاز، و **چند درصد بدون ویرایش** (۳) و **چند درصد نیاز به بازنویسی کامل** (۰ و ۱)،
  هر کدام با بازه‌ی اطمینان.
- چند درصد **چیزی از خودش ساخت**.
- **از پاسخ‌هایی که در عمل می‌رفتند**، چند تا غلط یا ساخته‌شده بود. مهم‌ترین عدد ایمنی.
- **از پاسخ‌هایی که سیستم ساکت می‌ماند**، چند تا خوب بود. یعنی سیستم چقدر محتاط است.
- شکست فراخوانی، زمان پاسخ، و هزینه‌ی هر پیام.
- **رودررو:** در چند پرسش اولی بهتر بود، دومی، یا مساوی، و آیا این تفاوت از شانس قابل‌تشخیص است.
- **جدول آستانه‌ی اطمینان:** اگر آستانه ۰٫۵ تا ۰٫۹ بود چه می‌شد. جوابِ «۰٫۷ درست است؟» همین‌جاست.

## چطور تصمیم بگیریم (پیشنهاد من، نه قانون)

مدل ارزان‌تر بماند، اگر هر سه برقرار باشد:

1. در رودررو تفاوت **معنی‌دار به نفع مدل گران‌تر** نباشد، یا «قابل تشخیص نیست» بگوید.
2. از پاسخ‌های **ارسال‌شده**، تعداد غلط یا ساخته‌شده‌اش بیشتر از مدل گران‌تر نباشد.
3. درصد «بدون ویرایش»اش بیشتر از ۱۰ واحد کمتر نباشد.

اگر نمونه کمتر از ۳۰ بود، گزارش خودش می‌گوید که نشانه است نه نتیجه؛ پرسش بیشتر بگیرید.

## آنچه این ابزار نمی‌داند

- **کور کامل نیست.** سبک نوشتار هر مدل (فهرست، طول، لحن) می‌تواند لو بدهد.
- **تک‌پیام است.** تاریخچه‌ی گفتگو و حافظه‌ی دانشجو در کار نیست؛ مسیر «یک پرسش» سنجیده می‌شود.
- **نمونه‌ی کم نتیجه‌ی قطعی نمی‌دهد.** برای همین بازه و آزمون آماری را کنار میانگین می‌بینید.
- **کیفیت یک داور، کیفیت یک داور است.** سلیقه‌ی یک منتور را می‌سنجد.
- **آستانه‌ی ۰٫۷** را خود مدل گزارش می‌دهد و هر مدل متفاوت؛ جدول آستانه نشان می‌دهد برای هر کدام
  چه عددی امن‌تر است، ولی تغییرش تصمیم جداست.
