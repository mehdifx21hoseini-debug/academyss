# خروجی پایگاه دانش برای MENTORAI CORE

این پوشه خروجی رسمی پایگاه دانش است برای مصرف پروژه‌ی CORE
(`mentorai/`). دو فایل تولید می‌شود:

| فایل | چیست |
|---|---|
| `mentorai_kb_vNNN.csv` | خود پایگاه دانش، با همان هشت ستونی که `mentorai kb-import` می‌خواند |
| `mentorai_eval_vNNN.csv` | مجموعه‌ی آزمون بازیابی (`question,expected_question`) |

## ساخت و وارد کردن

```bash
python3 tools/kb_export_core.py                    # فقط منابع آکادمی
python3 tools/kb_export_core.py --include-general   # به‌علاوه‌ی لایه‌ی دانش عمومی

mentorai kb-import --file exports/core/mentorai_kb_vNNN.csv
```

نسخه‌ها هرگز بازنویسی نمی‌شوند؛ هر اجرا فایل `vNNN` تازه می‌سازد.

## نگاشت

| ستون CORE | از کجا می‌آید |
|---|---|
| `source_class` | `ACADEMY_PRIMARY` و `ACADEMY_DERIVED` → `official` · `MENTOR_VERIFIED` → `mentor` |
| `category` | از پیشوند شناسه (دوره مقدماتی، هوش هیجانی، اکسپرت SSProX…)؛ برای پرسش‌های منتور از `intent` |
| `question` | `related_questions` — عبارت واقعی دانشجو، نه عنوان رکورد |
| `answer` | `chunk_text` پس از پاک‌سازی |
| `authority` | نوع رکورد، **مشروط به تأیید انسانی** (پایین‌تر) |
| `valid_until` | عمداً خالی است (پایین‌تر) |
| `owner` | نویسنده‌ی منبع |
| `notes` | شناسه‌ی رکورد + هر چیزی که نباید به دانشجو گفته شود |

## چهار قاعده‌ای که این مبدل رعایت می‌کند

**۱. تأیید، سطح اعتبار را تعیین می‌کند.** در منشور پروژه «پوشش» با «تأیید»
یکی نیست: وجود یک رکورد یعنی موضوع ثبت شده، نه اینکه مربی مجاز است آن را
به‌عنوان حرف رسمی آکادمی بگوید. پس فقط رکوردهای `APPROVED` می‌توانند
`fact` یا `policy` شوند؛ هر چیزی که هنوز تأیید نشده حداکثر `guidance`
می‌شود و رکوردهای `REVIEW_REQUIRED` اصلاً خروجی نمی‌گیرند.

**۲. `source_class` منبع را نشان می‌دهد، نه مفید بودن را.** CORE از این ستون
استفاده می‌کند تا تصمیم بگیرد چه چیزی را می‌شود به‌عنوان قیمت و قانون و شرط
گفت. لایه‌ی دانش عمومی (مفاهیم پایه، متاتریدر، روان‌شناسی عمومی) نه منبع
آکادمی است نه پاسخ منتور؛ پس به‌صورت پیش‌فرض خروجی نمی‌گیرد. با
`--include-general` به‌عنوان `mentor` + `guidance` اضافه می‌شود و منشأ
واقعی‌اش در `notes` نوشته می‌شود.

**۳. متن رکورد دو مخاطب دارد و جدا می‌شود.** `chunk_text` ما برای این پروژه
نوشته شده و خط‌هایی با ⚠️ و 💡 و 📘 دارد که خطاب به مربی است، نه دانشجو.
این خط‌ها به `notes` می‌روند — همان ستونی که CORE برایش نوشته «توضیح داخلی
که نباید به دانشجو گفته شود». ارجاع‌های داخلی (`ACA-…`) و نشانه‌گذاری
مارک‌داون هم از پاسخ حذف می‌شوند، چون CORE پاسخ را بدون `parse_mode`
می‌فرستد.

**۴. رکوردهای لحن، دانش نیستند.** `ACA-STY-*` می‌گویند مربی *چطور* حرف بزند.
جای آن‌ها لایه‌ی پرامپت CORE است (`mentorai/src/mentorai/ai/prompt.py`)، نه
شاخص بازیابی که به سؤال دانشجو جواب می‌دهد. پس خروجی نمی‌گیرند.

## چرا `valid_until` خالی است

هیچ‌کدام از رکوردهای زمان‌مند ما تاریخ انقضای واقعی ندارند — فقط علامت
`time_bound` دارند با توضیح («مربوط به زمان ضبط دوره»، «به شرایط روز بستگی
دارد»). ساختن یک تاریخ الکی بدتر از خالی گذاشتن است، پس ستون خالی می‌ماند و
هشدار زمان‌مندی در `notes` می‌آید.

## چرا عبارت‌های جایگزین به فایل آزمون می‌روند

هر رکورد ما چند شکل واقعی از یک سؤال دارد. اگر هر کدام یک ردیف جدا می‌شد،
سه نسخه از یک پاسخ در شاخص می‌نشست و جای محتوای دیگر را می‌گرفت — دقیقاً
همان چیزی که راهنمای خود CORE از آن پرهیز می‌دهد («یک موضوع، یک مدخل
مرجع»). پس عبارت اول ستون `question` می‌شود و بقیه به فایل آزمون بازیابی
می‌روند: اگر CORE نتوانست رکورد را از عبارت دوم پیدا کند، آزمون خودش
می‌گوید.

## آنچه گزارش می‌شود و پنهان نمی‌ماند

خروجیِ اجرا این‌ها را نام می‌برد:

* `moved` — عبارتی که رکورد ضعیف‌تر به رکورد قوی‌تر واگذار کرده
* `clash` — رکوردی که همه‌ی عبارت‌هایش قبلاً گرفته شده بوده و کنار گذاشته شد
* `skip` — و دلیل هر گروه کنارگذاشته‌شده

رکوردها به ترتیب قدرت پردازش می‌شوند (اول تأییدشده‌ها، بعد منابع آکادمی،
بعد اطمینان بالاتر)، تا هر سؤال به قوی‌ترین رکوردی برسد که جوابش را دارد.
